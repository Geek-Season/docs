# Бизнес-требования

> Версия 1.0 от 22.10.2026 · Ответственный: системный аналитик

## 1. Проблема

Школьник, готовящийся к ЕГЭ по информатике, решает задачи из разрозненных источников:
сборников, PDF, сайтов, заданий репетитора в мессенджере. В результате:

- нет единого места, где задачи разложены по номерам экзамена;
- никто не считает, какие номера уже отработаны, а какие нет;
- непонятно, что повторять в первую очередь;
- нет регулярности — прогресс не виден, мотивация падает.

Репетитор, который ведёт 10–30 учеников, тратит время на ручную раздачу
и проверку задач и держит в голове, у кого какие слабые темы.

## 2. Цель

**Geek Season** — платформа, где задачи ЕГЭ разложены по номерам экзамена,
ответы проверяются автоматически, а каждый ответ ученика превращается в статистику:
что решено, где ошибки, сколько дней подряд он занимается.

Первая версия — для ученика. Следующая — для репетитора и его учеников.

### Метрики успеха

| Метрика | Как измеряем |
|---|---|
| Ученик занимается регулярно | Серия дней в профиле; доля учеников с серией ≥ 3 |
| Ученик закрывает номера целиком | Доля номеров с прогрессом 100 % |
| Время на проверку части 1 | 0 — проверка автоматическая и мгновенная |

## 3. Роли

| Роль | Кто это | Статус |
|---|---|---|
| **Гость** | Не вошёл | Видит номера и задачи, может проверять ответы, но они не сохраняются |
| **Ученик** | Школьник 10–11 класса | ✅ Реализован: вход через Telegram, решение, статистика |
| **Репетитор** | Преподаватель, готовящий к ЕГЭ | ⏳ Группы учеников, задания, аналитика по ученикам |
| **Администратор** | Команда платформы | ✅ Управляет банком задач через страницу «Редактор» |

## 4. Границы продукта

**Входит:**
- ЕГЭ по информатике: номера 1–27 (19–21 — одна карточка), задачи-прототипы к каждому;
- задачи с кратким ответом: число, слово, последовательность, несколько чисел;
- вход без пароля — через Telegram-бота;
- статистика ученика.

**Не входит (сознательно):**
- выполнение программного кода на сервере — ученик решает задачи по программированию
  в своей IDE и вводит ответ (как на экзамене);
- оплата, видеосвязь, онлайн-уроки;
- официальный банк ФИПИ — задачи авторские или добавлены вручную;
- другие предметы и ОГЭ — модель данных это допускает, но в первой версии их нет.

## 5. Требования

Приоритет: **M** — must, **S** — should, **C** — could. Статус: ✅ готово, ⏳ в плане.

### 5.1 Вход и профиль

| ID | Требование | Приор. | Статус |
|---|---|---|---|
| BR-01 | Вход без пароля через Telegram-бота: QR-код на сайте → подтверждение в боте | M | ✅ |
| BR-02 | Альтернатива QR: команда `/login` в боте выдаёт 6-значный код для ввода на сайте | M | ✅ |
| BR-03 | Первый вход создаёт ученика автоматически (имя и @username из Telegram) | M | ✅ |
| BR-04 | Ключ QR и код одноразовые и живут 5 минут; не более 5 попыток ввода кода в минуту | M | ✅ |
| BR-05 | Вход сохраняется после перезагрузки страницы; есть выход | M | ✅ |
| BR-05a | Имя на сайте (ник) — показывается везде вместо имени из Telegram (шапка, профиль, рейтинг); 3–20 символов, буквы, цифры, пробел, `_`, `-`; фильтр мата; повторы можно; без ника — имя из Telegram; админ может сбросить | S | ✅ |
| BR-05b | Аватарка: по умолчанию фото из Telegram (обновляется при входе); можно загрузить свою с обрезкой до квадрата и вернуть фото из Telegram; видна в шапке, профиле и рейтинге; админ может сбросить | S | ✅ |
| BR-05c | Настройки профиля в окне по шестерёнке: аватарка, имя, пол (М / Ж / не указан; нигде не показывается). В профиле — @username и «Занимаюсь с <месяц> <год>» | S | ✅ |

### 5.3 Решение и проверка

| ID | Требование | Приор. | Статус |
|---|---|---|---|
| BR-12 | Ученик вводит ответ и сразу видит: верно / неверно. Верно — правильный ответ и разбор; неверно — пробует снова, после трёх ошибок может открыть ответ и разбор | M | ✅ |
| BR-12a | Номера 19–21: одно условие игры и три вопроса, у каждого своё поле ответа и свой разбор; задача решена, если верны все три | M | ✅ |
| BR-13 | Сравнение ответов: числа как числа (4 = 4.0, 0,25 = 0.25), слова без учёта регистра, несколько чисел по порядку | M | ✅ |
| BR-14 | Правильный ответ и разбор не отдаются API до верного ответа или трёх неверных | M | ✅ |

## 7. Технологический стек

| Слой | Технология | Почему |
|---|---|---|
| Backend | Python 3.12, FastAPI, Pydantic 2 | Swagger генерируется из кода — контракты всегда актуальны; строгая валидация входных данных |
| ORM, миграции | SQLAlchemy 2, Alembic | Модели-классы (ООП), версионирование схемы |
| БД | PostgreSQL 16 | Транзакции, внешние ключи, агрегаты для статистики |
| Временные данные | Redis 7 | Одноразовые ключи входа с TTL, счётчик попыток, идущий пробник с TTL и защита от двойного старта, рейтинг (sorted set) |
| Бот | aiogram 3 | Вход без пароля |
| Брокер сообщений | RabbitMQ 3.13, pika | Достижения и уведомления — в фоне: сайт не ждёт Telegram; повторы, «мёртвые письма», веб-панель |
| Frontend | React 18 + Vite | SPA из компонентов; быстрая сборка и прокси к API при разработке |
| Запуск | Docker Compose | NFR-01 |

## 8. Глоссарий

| Термин | Значение |
|---|---|
| Номер | Позиция задания в ЕГЭ (1–27) |
| Прототип | Задача определённого номера |
| Попытка | Один отправленный ответ ученика на задачу |
| Решена | По задаче есть хотя бы одна верная попытка |
| Не решена | Попытки были, но ни одной верной |
| Серия | Дней подряд, в каждый из которых был хотя бы один ответ |
| Точность | Доля верных попыток среди всех |
