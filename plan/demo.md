# Сценарий демонстрации (чекпоинт 2)

Время показа — 7–10 минут. Ведёт PM (Кояков), демо — Яблуновский, вопросы — оба.

## Перед показом (за 10 минут)

- [ ] `docker compose up -d db redis`, `uvicorn`, `python -m app.bot`, `npm run dev` — всё запущено.
- [ ] В `.env` для показа: `EXAM_DURATION_MINUTES=5` — чтобы показать, как пробник завершается сам.
- [ ] Телефон с Telegram под рукой; в браузере открыты: сайт, `/docs` (Swagger), GitHub.
- [ ] Два аккаунта Telegram (свой и сокомандника) — чтобы рейтинг был не из одной строки.

## 1. Контекст (1 мин)

> Школьник готовится к ЕГЭ по информатике по разрозненным источникам и не видит своего прогресса.
> Geek Season раскладывает задачи по номерам экзамена, проверяет ответы автоматически и превращает
> каждый ответ в статистику: что решено, что повторить, сколько дней подряд занимается.

## 2. Демо — положительные сценарии (5–6 мин)

| # | Что делаем | Что говорим |
|---|---|---|
| 1 | «Войти» → сканируем QR телефоном → «Да» в боте | Вход без пароля. Ключ одноразовый, живёт 5 минут, хранится в Redis |
| 2 | «Задания» → сетка номеров, полоски прогресса | 27 номеров ЕГЭ; у вошедшего — сколько решено |
| 3 | Номер 17 → вводим `20 2` → «Неверно», затем `2 20` → «Верно» | Ответ из двух чисел; порядок важен. Метка «Решена», счётчик обновился |
| 4 | Фильтр «Нерешённые» | Только то, что ещё не решено |
| 5 | «Пробник» → «Начать» → вводим пару ответов → **F5** | Таймер на сервере: перезагрузка не сбросила ни время, ни ответы |
| 6 | «Завершить» → результат и разбор | Номера 26 и 27 — по 2 балла; разбор открывается только после завершения |
| 7 | «Профиль» | Решено, точность, серия, график за 14 дней, «Что повторить» → «Потренировать» |
| 8 | «Рейтинг» | Очко за задачу, решённую впервые; неделя и всё время; хранится в Redis |
| 9 | `/docs` (Swagger) | Контракты API генерируются из кода |
| 10 | GitHub: backend → `tests/`; `pytest` | 76 автотестов, включая негативные сценарии |

## 3. Вопросы, которые скорее всего зададут

**Негативные сценарии**

| Вопрос | Ответ |
|---|---|
| Ученик закрыл вкладку посреди пробника? | Время идёт на сервере (`deadline_at`). Вернётся — тот же пробник, ответы на месте, реальное оставшееся время |
| Отправил ответ после конца времени? | Сервер отвечает 409 «Время вышло» и сам завершает пробник с ответами, данными вовремя |
| Дважды нажал «Начать»? | Блокировка в Redis (`SET NX` на 10 с): второй запрос получит 409, пробник будет один |
| Дважды нажал «Завершить»? | Результат тот же, без пересчёта — операция идемпотентна |
| Подсмотреть ответы через API во время пробника? | Ни один запрос не отдаёт правильные ответы до завершения — это проверено тестами |
| Подобрать 6-значный код входа? | Не больше 5 попыток в минуту с адреса (счётчик в Redis), код живёт 5 минут и одноразовый |
| Отправить `is_correct: true` в запросе? | Pydantic с `extra="forbid"` → 422; верность считает только сервер |
| Удалить задачу, которую уже решали? | Не удаляем, а архивируем — иначе сломается статистика |
| Redis упал / очистился? | Пробник найдётся по базе, рейтинг пересоберётся из таблицы `attempts`. Redis — ускоритель, не источник правды |
| Чужой пробник по id? | 404 — не раскрываем даже факт существования |

**Решения и расширяемость**

| Вопрос | Ответ |
|---|---|
| Почему Python, а не ASP.NET? | FastAPI так же генерирует Swagger из кода; Pydantic — строгие контракты; SQLAlchemy — модели-классы. Согласовано с преподавателем |
| Зачем Redis? | Данные с временем жизни (коды входа, идущий пробник) и рейтинг: sorted set сразу отдаёт топ и место без пересчёта по таблице |
| Почему «решено» не хранится в таблице? | Вычисляется из попыток — нет дублирования, нечему рассинхронизироваться |
| Как добавить предмет? | Модель номеров не привязана к информатике: новый предмет — новый набор номеров. Следующий шаг — таблица предметов |
| Как растёт нагрузка? | Индекс `(user_id, task_id)` на попытках; рейтинг в Redis; backend без состояния — можно запускать несколько копий |
| Где ООП? | Модели SQLAlchemy — классы; модули с разделением ответственности: router → service → models; исключения предметной области (`TimeIsUp`, `ExamFinished`) |

**Процесс**

| Вопрос | Ответ |
|---|---|
| Почему пропустили чекпоинт 1? | Честно: отстали с документацией. Материалы чекпоинта 1 (требования, юзкейсы, ERD, API, roadmap) сданы в этом репозитории |
| Почему вас двое? | Состав зафиксирован; объём сокращён: сначала роль ученика, репетитор — следующий этап |
| Подводные камни? | Порт 5432 занят локальным PostgreSQL — перенесли на 5433; часовой пояс в статистике (ответ в 00:30 по Москве — «сегодня»); равные очки в рейтинге должны давать общее место |
