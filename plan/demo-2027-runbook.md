# Выпуск перенумерации демоверсии 2027

Контракт API 0.16.0, ветки `feature/demo-2027-final`. Backend выпускается первым.

## Согласованные темы

| Текущий номер | Название |
|---|---|
| 3 | Базы данных |
| 9 | Электронные таблицы |
| 10 | Поиск в текстовом редакторе |
| 13 | IP-адресация и маски подсети |
| 18 | Робот в таблице |
| 23 | Исполнитель |
| 26 | Сортировка и обработка данных |
| 27 | Кластеризация |

## Подготовка и порядок

1. Сохранить резервную копию базы штатным способом окружения. Зафиксировать
   примеры старого пробника, домашки, попыток графов и PTS по ID тем.
2. В миграции заполнить исторические снимки `number_code`/`number_title`
   до изменения кодов и названий. Сохранить ID переносимых тем;
   создать отдельную тему №10. Графам назначить `legacy-23`, `is_active=false`,
   их задачам — `is_archived=true`.
3. На локальной базе проверить `alembic upgrade head` → `alembic downgrade -1` →
   `alembic upgrade head`, затем полный `pytest`. Эти проверки выполняются в backend.
   Убедиться, что пересчёт PTS при запуске сохраняет историю по темам,
   включая архивные графы в общем PTS, и исключает графы из прогноза.
4. В окно обслуживания остановить приём новых работ и фоновые записи. Выпустить
   backend с версией 0.16.0, применить миграцию и проверить старые работы.
   `docs/api/openapi.json` уже экспортирован из работающего локального API 0.16.0.
5. Импортировать подготовленный поиск №10 командами ниже, повторить пересчёт PTS
   после наполнения банка и сравнить отчёт с копией БД. Только затем открыть новые работы.
6. Во frontend выполнить `npm run lint` и `npm run build`, выпустить frontend и проверить
   страницы на обычной и мобильной ширине. Конфигурацию линтера в рамках этой задачи не менять.

## Поиск №10: файлы и импорт

Проверка 15.11.2026: публичный `https://kompege.ru/api/v1/task/number/10` содержит
192 видимые задачи с ответами и файлами. Выгрузка подготовлена в ignored
`backend/data/kompege`: 206 исходных вложений, для импорта 205 вложений и одна картинка.
У задачи 7082 RTF пропускается как неподдерживаемый, другие форматы доступны.
`manifest-10.json` содержит SHA-256 оригиналов, payload и результат офлайн-проверки.
В локальный изолированный API импортированы все 192 задачи, ошибок нет.
Это не подтверждает импорт в рабочую базу.

Команды из `backend/` (адрес и токен задаются для выбранного окружения):

```powershell
.venv/Scripts/python.exe -m scripts.kompege.prepare_search --in data/kompege
.venv/Scripts/python.exe -m scripts.kompege.import_ --api "<API>" --in data/kompege --number 10 --skip-existing --dry-run
.venv/Scripts/python.exe -m scripts.kompege.import_ --api "<API>" --in data/kompege --number 10 --skip-existing
```

`GEEK_TOKEN` передаётся через окружение. Не использовать `--update`: существующие
external ID, включая архивные, должны остаться без перезаписи. При конфликте
содержимого остановиться и проверить задачу, а не менять старый эталон.
Повторный импорт должен показать 192 уже существующих задачи и ноль созданных.
Проверить 205 вложений и одну картинку, доступность скачивания и отсутствие дублей.

Миграцию отдельно проверяет `python -m scripts.check_demo2027_migration` на пустой
выделенной БД с окончанием `_check`, заданной через `DATABASE_URL`. Скрипт создаёт
пример старой классификации и проверяет upgrade → downgrade → upgrade, ID,
попытки, снимки и прежнюю архивность. Рабочую БД и общую `geek_test` не использовать.

## Проверка приёмки

- Старые домашки и пробники показывают прежние номер и название; баллы,
  ответы и разборы сохранены. Тренировочная ссылка пробника ведёт на текущую тему.
- Для части 19/20/21 ссылка ведёт на `19-21`.
- При `task_number=null` тренировочной ссылки нет. Если старый API не прислал поле,
  работает прежний выбор карточки; это режим совместимости, а не распознавание архива.
- Последние ответы графов показывают «№23 · архив» без ссылки;
  отсутствие `is_archived` совместимо с прежним отображением активной попытки.
- Графов нет в каталоге, выборе номера и прогнозе; их история и общий PTS сохранены.
- Названия совпадают с таблицей, новый №10 не наследует PTS другой темы.
- Полный вариант с заполненными пулами по всем номерам имеет 29 первичных баллов; шкала 2026 сохраняется.

## Откат

До отката оценить новые данные, созданные после выпуска, и сохранить резервную копию.
Сначала убрать frontend, требующий нового контракта, затем использовать проверенный
план отката backend и базы для конкретного окружения. Не заменять обратную миграцию
ручной перестановкой кодов: это может повредить снимки и связи PTS.
Команды выкладки и восстановления зависят от окружения и здесь не задаются.

Миграция хранит исходные названия/коды/позиции и архивность графов в служебной
таблице `demo_2027_migration_backup`. Downgrade откажется удалять новый №10, если
на него уже ссылаются задачи или PTS. После импорта/приёма новых работ требуется
отдельный план восстановления с резервной копией, а не принудительный downgrade.
